# Linux 0.4.7

Consulta `https://firulai.redsauce.net/api/agents/update-catalog` sin enviar tokens.
Firulai obtiene de RSM la version Linux y Windows, sin alterar la API de RSM ni
los permisos de cuenta. El catalogo esta desplegado y comprobado en Firulai 2026-10-16 Build 01.

La version Linux seleccionada determina el tag concreto del repositorio oficial.
Se validan HTTPS, formato estable, version del script y sintaxis. Se actualizan
rs_agent.sh, api_endpoint.sh, uninstall.sh y rs_agent_runner.sh; se conserva la
configuracion, el estado y la copia del agente anterior. Hay recuperacion de
archivos ante un error de reemplazo detectado, pero no una transaccion atomica
de varios archivos ante un corte de corriente. Linux no incorpora la firma RSA
del instalador Windows.

El runner revisa cada minuto si corresponde consultar. Solo hace la consulta
al primer tick tras arrancar, despues de una hora desde el ultimo exito, o al
vencer el reintento de 5, 10, 20 y despues 60 minutos. Anade 0-60 segundos por
equipo y persiste el plazo, los fallos y el ID del arranque. Tras reanudarse,
cron actua en el siguiente minuto; systemd usa calendario persistente.

La instalacion migra su watchdog cron/timer sin cambiar otros trabajos. El nuevo
agente recibido por el actualizador anterior renueva tambien el runner y adapta
el programador. El modo de usuario conserva los requisitos de sesion/linger;
no se activa linger automaticamente. Un fallo de esa migracion queda registrado
y se reintenta en futuras ejecuciones.

El inventario conserva su ejecucion diaria a las 03:00 y los reintentos a los
30 minutos. Ni un envio completado ni un fallo de envio suprimen las consultas
de actualizacion. El bloqueo de ejecucion evita reemplazar scripts durante un
inventario y se conserva a traves del exec posterior a una actualizacion.

El instalador de esta release obtiene sus propios archivos desde 0.4.7, no main.
Las instalaciones desde tags estables mantienen la actualizacion automatica;
las ramas de prueba siguen desactivandola.

Pruebas locales bajo WSL: sintaxis; orden de versiones; catalogo, plazo horario,
reintentos, arranque, opt-out; cuatro descargas fijadas al tag; paquete incorrecto;
migracion cron con trabajos ajenos; runner con inventario fallido/completado;
24 comprobaciones de estados/cobertura y admision. La validacion Ubuntu 24.04
en una VM aislada tambien ha comprobado la migracion con systemd real, timer
activo, arranque y ejecucion de la unidad, ademas del catalogo publico HTTPS.
Evidencia: https://github.com/Redsauce/firulai-linux-agent/actions/runs/38883715305
Queda por observar la actualizacion y el inventario de un cliente Linux real.
Las pruebas no han modificado ningun agente instalado.
